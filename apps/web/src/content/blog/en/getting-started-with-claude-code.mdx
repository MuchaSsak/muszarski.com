Claude Code is Anthropic's agentic coding tool: it reads your code, edits files and runs commands, in the terminal, your IDE, a desktop app or the browser. To start you need a paid plan or a Claude Console account and one command. Day to day, three habits matter most: a short CLAUDE.md, a plan before code and a check on every change.

> **TL;DR**
>
> - **Start:** a paid plan or a Claude Console account, one install command, then `claude` in your project folder and a few questions about the code before you change anything.
> - **Every day:** a short CLAUDE.md, plan mode before a bigger change, `/clear` between unrelated tasks, and every change checked with a test, a build or a screenshot.
> - **Honestly:** permissions are enforced by Claude Code, not by CLAUDE.md, and the cost depends on your plan, model and way of working.

## How do you install Claude Code?

You need a paid plan (Pro, Max, Team or Enterprise), a Claude Console account with prepaid API credits, or a cloud provider. The free plan doesn't include Claude Code. On 18 October 2026, Pro cost 20 USD a month (17 USD billed yearly) and Max started at 100 USD. Prices change, so check them before you buy.

```bash
# macOS, Linux, WSL
curl -fsSL https://claude.ai/install.sh | bash
```

```powershell
# Windows PowerShell
irm https://claude.ai/install.ps1 | iex
```

Then open a new terminal and run `claude --version`. If the shell doesn't know the command, the install folder isn't on your PATH (the docs have a page for that). On Windows the docs recommend Git for Windows so Claude Code can use Bash; without it, it uses PowerShell. The native install updates itself; Homebrew and WinGet installs you update by hand.

## What does the first session look like?

```bash
cd ~/projects/my-project
claude
```

The first run logs you in through the browser. Then start with questions, not changes: "what does this project do?", "where is the entry point?", "explain the folder structure". Claude reads the files it needs, so you don't paste anything.

| Command | What it does |
| --- | --- |
| `/help` | lists the available commands |
| `claude -c` | continues the last conversation in this folder |
| `claude -r` | lets you pick an older conversation |
| `/clear` | clears the context between unrelated tasks |

## What goes into CLAUDE.md?

CLAUDE.md is a file Claude reads at the start of every session. `/init` generates a first version from your code, and you trim it. The docs suggest putting in:

- commands Claude can't guess;
- style rules that differ from the defaults, and how to run the tests;
- repository habits (branch names, pull requests);
- architecture decisions, environment quirks and non-obvious traps.

Leave out what Claude can read from the code, long tutorials and file-by-file descriptions. Aim for under 200 lines and ask the docs' question of every line: would Claude make a mistake without it? If not, cut it.

Two things are easy to miss. `CLAUDE.local.md` in the project folder holds your private rules, so add it to `.gitignore`. `/context` shows whether the file actually loaded.

My CLAUDE.md is 76 lines, because the rest of the knowledge lives in a wiki, described in [An LLM wiki: project memory for Claude Code](/en/blog/llm-wiki-project-memory-for-claude-code/).

Plan mode covers the first two: press `Shift+Tab` until the status bar shows `⏸ plan mode on`, or run `claude --permission-mode plan`. In this mode Claude reads files and answers questions but doesn't edit your source.

For bigger features, the docs suggest asking Claude to interview you and write a spec, then implementing it in a fresh session. For small things a plan is overhead: if you can describe the diff in one sentence, skip it. On this site the whole of phase zero was planning: research and the wiki, before any product code.

## How do permissions work?

Whether Claude Code asks before acting depends on the mode. `Shift+Tab` cycles through them and the status bar shows the current one.

| Mode | What it does |
| --- | --- |
| `default` (Manual) | only reads without asking; asks before edits, commands and network |
| `acceptEdits` | accepts file edits and simple file commands on its own |
| `plan` | reads and plans, doesn't edit your source |
| `auto` | no routine prompts; a separate classifier checks actions in the background |
| `dontAsk` | denies anything that would need a prompt, except what you allowed before |
| `bypassPermissions` | skips prompts; only in an isolated container or virtual machine |

From version 2.1.283, sessions in the terminal and VS Code start in `auto`, but your settings matter too, so watch the status bar. `/permissions` shows the allow, ask and deny rules, checked in the order deny, ask, allow. And the key point: the rules are enforced by Claude Code, not by the model. A ban written in CLAUDE.md shapes what Claude tries to do, but it blocks nothing.

## How do you give it context?

- **Be specific.** Which file, which scenario, what "fixed" means. Instead of "fix the login", write: login fails after the session expires, check the token refresh in `src/auth/`, write a test that reproduces it first, then fix it.
- **Point at things.** Reference files with `@`, paste screenshots, give documentation URLs.
- **Show a pattern.** Point at existing code Claude should follow.
- **Paste it whole.** Give error messages in full and ask for the cause, not for the error to go away.
- **Pipe it in.** Logs go in without copying: `cat error.log | claude -p "explain this error"`.

## How do you check its work?

The docs put it simply: Claude stops when the work looks done. Without a check you can run, the only signal is "looks fine", and you become the verification loop. So give it something that returns a result: tests, a build's exit code, a linter, a screenshot to compare with the design. Ask for evidence, not reassurance.

On this site, "done" means typecheck, lint, unit and e2e tests. Then Playwright screenshots at 390, 1024 and 1920 pixels that someone actually looked at, and axe for AA contrast and reduced motion. When a change can move the score, mobile Lighthouse has to stay at 90 or above.

Another example: during my internship at Neoteric, a Polish software house, I built Clockful, a time tracking app with roles, using only AI agents. It came from a 15-requirement spec in about 9 days (an estimate from the repository's dates), guarded by automated tests in Vitest and Playwright.

## What mistakes happen most often?

The docs name five common failure patterns:

- **The kitchen-sink session.** One task, then something unrelated, then back again. The fix: `/clear` between unrelated tasks.
- **Correcting over and over.** After two failed corrections, `/clear` and write a better first prompt with what you learned.
- **An overloaded CLAUDE.md.** The important rules get lost in the noise. Trim it hard.
- **Trust without checking.** The code looks plausible but misses edge cases. If you can't check it, don't ship it.
- **Endless exploring.** "Investigate X" with no scope ends in hundreds of files read. Narrow the question or hand it to a subagent.

Two rescue tools on top. `Esc` stops Claude mid-action, and a double `Esc` or `/rewind` restores the conversation, the code or both to a checkpoint. Checkpoints only track changes made by Claude's file editing tools, not by Bash commands, so they don't replace git.

And one more mistake, the one I wrote a hook for: decisions given only in chat disappear after compaction. Whatever should last goes in CLAUDE.md or a file a hook loads.

## How much does it cost?

- **Context is the main resource.** The model's work gets worse as the context window fills. Hence `/clear`, subagents for research and a short CLAUDE.md.
- **Limits.** On subscription plans, usage is included in the plan with limits, and `/usage` shows how much you've used. Subagents use it too.
- **A reference point.** In company rollouts, the docs put the average at about 13 USD per developer per active day and 150-250 USD a month, with 90% of users under 30 USD a day. That's data from companies paying for the API, not the price of your plan.
- **How to pay less.** Clear the context between tasks, give simpler tasks to a cheaper model (`/model`), turn off MCP servers you don't use.

## Limits

- **Not my bills.** They depend on the plan, the model and the way of working, so they'd say little about yours.
- **As of October 2026.** I checked the prices and the docs on 18 October. Claude Code changes fast, so look at the sources before you decide.

## Where to start tomorrow?

1. Install it, log in, open a small project.
2. Ask three questions about the code before you change anything.
3. Run `/init` and trim the result to what Claude can't read from the code.
4. Make your first change in plan mode, with a test Claude has to run.
5. Every correction you give a second time goes into CLAUDE.md.

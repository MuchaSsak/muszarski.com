# The CV sheet: how it works and how to change it

Read this before changing `CvSheet.astro`, the print route, `cv-sheet.mjs` or `cv-fonts.mjs`, and whenever
`bun run cv:sheet` prints a `FAIL`. Every rule here broke once (2026-10-08) and the reason is given, so a future change
can judge when a rule still applies.

## Contents

## 1. Anatomy

```
page 1 ┌───────────────────────────────────────────────┐  cobalt band, full bleed (no top margin on page 1)
       │ [photo 28mm]  MATEUSZ      (fitted)  [sticker] │  photo + h1 + sticker share one row
       │               MUSZARSKI                        │
       │               ────────────────────────────     │  .cs-id: role (CV Head 12 pt) + place · availability
       ├───────────────────────────────────────────────┤
       │ email ▪ host ▪ github ▪ linkedin               │  navy contact bar (.cs-bar), links spelled out
       ├───────────────────────────────────────────────┤
       │ ▪ PROFILE ──────────────────────────────────── │  h2: pink tab, label, navy rule to the edge
       │ [rail 27mm] │ text in the wide column           │  .cs-wide = rail + gutter of left margin
       │ ▪ SKILLS ──  "Group: a · b · c" one row each    │
       │ ▪ EDUCATION / EXPERIENCE / SELECTED PROJECTS    │  .cs-entry: grid [rail | 1fr]; EDUCATION_FIRST
       │ date │ Title (h3)                               │    .cs-when in the rail, rows 1-2
       │      │ org (slate)                              │    then bullets (pink squares), links
page 2 │ MATEUSZ MUSZARSKI · CV                    2 / 2 │  @page margin boxes: both outline SVGs (no text)
       │ ▪ QUALIFICATIONS AND TRAINING                   │  .cs-cred: bold body head "title · issuer", items
       │ ▪ LANGUAGES        │ ▪ INTERESTS                │  .cs-pair, two columns; one language per line
       │ ┌ CONTACT  hi@…  web CV · GitHub ┐▌            │  pink contact slip, pinned to the last page's foot
       │ └────────────────────────────────┘▌            │
       │ (pl) recruitment clause, small                  │
       └───────────────────────────────────────────────┘
```

Section order and why: `content.md` § 3. Page 1 must sell him alone: who, role, place, contact, stack, school, work.
`EDUCATION_FIRST` in the sheet's frontmatter puts Education before Experience while he is at school; set it to `false`
after graduation. Empty lists and blocks render nothing.

Without a photo (`--no-photo`, or no photo file) the band drops to two columns: the name takes the photo's column at
its capped size (18.2 mm, so the band keeps its height) and the sticker stays right.

Files: `components/cv/CvSheet.astro` (markup + scoped CSS), `pages/[locale]/cv/print-v2/index.astro` (`@page`, the
global reset, `--d` default, metadata, digest), `styles/cv-fonts.css` + `lib/cv-fonts.gen.ts` (generated by
`cv:fonts`), `scripts/cv-sheet.mjs` (build, serve, fit, print, check).

## 2. How it fits

- **`--d`** (0 = densest, 1 = roomiest) is one CSS variable on `:root`. Every body size and gap reads it: body
  `10pt + 0.8pt·d`, line height `1.3 + 0.1·d`, section gap `4.2 + 3.4·d` mm, entry gap `2.2 + 1.8·d` mm, list gaps.
  The band, the labels (7.6 pt) and the bar (8.2 pt) are fixed: they are chrome, not content.
- `cv-sheet.mjs` prints at `d = 0`. More than 2 pages there = **error** (cut content, `content.md` § 7). If it fits one
  page, it searches the roomiest one-page `d`; one page wins when that is ≥ 0.4 (`ONE_PAGE_MIN_D`), so a short CV
  doesn't get crammed onto one sheet. Otherwise the roomiest two-page `d` (6 halvings, ~1/64).
- **End gap:** then it halves `--end-gap` over 0-270 mm (8 steps) for the largest top margin on the contact slip that
  keeps the page count, minus 0.5 mm. That pins the slip to the foot of the last page. Above `MAX_END_GAP` (40 mm)
  the slip follows the content instead: a band alone at the foot of a mostly empty page reads as a layout error.
- Entries never split across pages (`break-inside: avoid`); sections may. So page 1 can end with a gap the height of
  the next entry (6-20 mm today). That is the price of whole entries; don't fight it with `orphans` tricks.
- The report: `d`, pages, `lastPageFill` (body text only, before the end gap), `endGapMm`, fonts, links, problems,
  warnings. `warn page 2 holds only N%` (below 30%): add substance or cut to one page. `warn facts still to confirm`
  lists entries with `placeholder: true` in `cv.ts` (`data-cv-placeholder` on the article).
- `--d` reported near 0 means no headroom: the next addition needs a cut first. Say so in the report. Polish runs
  longest (0.08 on 2026-10-08, with the 10 pt floor).

## 3. Tokens

- Colours (the site's Cobalt palette; this page loads no global CSS): cobalt `#2433ff` (band, dates, labels, skill
  groups), navy `#0a0d33` (text, bar, rules, shadows), ice `#eef0ff` (text on cobalt), pink `#ff4fb8` (markers, photo
  shadow, the slip; never text on white, 2.97:1), slate `#4b4f78` (meta text, 7.8:1).
- Type roles, one static font each: CV Text (400/100, body), CV Strong (700/100, bold inline, meta, bar), CV Head
  (850/78 condensed, job and project h3, role, slip email), CV Label (800/125 expanded, h2 labels; the running head
  and page number are its outlines), CV Name 1/2 (900, fitted). Six steps of size: label 7.6 pt, band 8.2 pt, meta
  0.9·fs, body fs (also the credential head lines, in CV Strong), title 1.2·fs, slip email 2.1·fs (+ the role's 12 pt
  and the fitted name). Labels, the contact bar and the band's role line are chrome: labels and bar 8.2 pt (the bar's
  one line holds the LinkedIn address only up to 8.2 pt; the email repeats large in the slip), the availability line
  at the meta size. Adding a step needs a reason.
- Geometry: edge 14 mm (padding, see § 8), rail 27 mm, gutter 5 mm, photo 28 mm, sticker 26 mm, hard shadows 1.8 mm.

## 4. Invariants and why

| Rule | Why (what broke) |
| --- | --- |
| Nothing that holds text is `position`ed or `transform`ed (no `position: relative` either) | Chrome writes PDF text in paint order; a positioned box paints after in-flow content, so the contact bar came before the name and dates after their bullets. Use grid columns and in-flow pseudo-elements |
| Decoration that is text-like (sticker, running head) is drawn as outlines | outlines carry no text: no second name, no "PORTFOLIO" in the parser's output. Outlines may rotate |
| Static font instances only, `font-synthesis: none` | a variable font, or a synthesised bold (an invalid `font` shorthand once caused one), prints as Type 3: poor extraction in some ATS and viewers |
| Only glyphs Anybody has | missing ones (`→ ↗ ← ■ ✓`, primes, U+202F) fall back to a system font, often Type 3. Squares are CSS boxes |
| Letter-spacing ≤ 0.05 em on text | wider tracking splits words in extractors (`E D U C A T I O N`) |
| Every link is visible text, underlined; email is `mailto:` | paper readers type it; parsers read text, not annotations; colour alone fails greyscale |
| Real text in DOM = reading order: title, org, date, bullets | the check compares every block's start in DOM order with the text layer |
| A date shares its title's baseline (`align-self: baseline`, no padding on `.cs-when`) | extractors and ATS parsers pair a date with the title on its row; 1-2 pt off and the date landed beside the wrong entry (v5, en) |
| `@page` side margins 0, the 14 mm edge as `.cs` padding | Chrome clips anything painted into a page margin: the bands couldn't bleed |
| Page 1 has no top margin and no margin boxes | the band opens the paper and the text layer must start with the name |
| Body never below 10 pt (`d = 0`); 9 pt only for meta lines | print guidance (UT Austin, Tech Interview Handbook: never under 10 pt); overflow is a content problem, not a type problem |
| The default `--d` lives on `:root`, never on `.cs` | a value on `.cs` shadows the one the script sets on `<html>`: `--d` silently did nothing |
| Margin resets are global in the page (`:is(h1,h2,h3,p,ul) { margin: 0 }`), not scoped | Astro's scoped `.cs :where(…)` gains the scope attribute's specificity and beat the class rules: every margin was 0 |

## 5. Checks

Each `FAIL` line from `cv:sheet`, and the fix:

| FAIL | Cause | Fix |
| --- | --- | --- |
| `N pages (max 2)` / `N pages even at the densest setting` | too much content | cut (`content.md` § 7); never lower the floor |
| `font X is Type3, not TrueType` | a variable font or synthesised style reached the page | static families only; check `font` shorthands (an invalid one drops to defaults); `font-synthesis: none` stays |
| `font X is a fallback` | a glyph Anybody lacks | find the character in the data or CSS `content`; replace it (words, a CSS box) or add it to the charset if Anybody has it (`fonts-shared.mjs`, then `cv:fonts`) |
| `the text layer starts with "…", not the name` | something paints before the h1 (a positioned element, margin-box text on page 1) | remove the positioning; keep page 1's margin boxes empty |
| `heading "…" missing or out of order` | a heading is positioned, hidden, or tracked wider than 0.05 em | same as above |
| `reading order: "…" comes too early` | that block paints out of DOM order | it, or an ancestor, is positioned/transformed |
| `reading order: "…" is missing` | text clipped, hidden, or drawn as outlines inside an `h1-3/p/li` | keep outlines in `aria-hidden` elements; check overflow |
| `"…" missing from the text layer` (`data-cv-must`) | the role, place or a contact item didn't print | as above |
| `link … is not clickable` | a `data-cv-link` href has no annotation | the element is hidden or covered; links must be real `<a href>` |
| `the date "…" is not on the baseline of "…"` | a date and its title sit on different baselines (padding, a different alignment, a wrapped title) | keep `align-self: baseline` on `h3` and `.cs-when`; no padding or margin on either |
| `the date check found only N of M titles` | the check couldn't find the titles in the text layer, so it proved nothing | a title is split into runs differently (a link, a span): match on its first 10 characters |
| `placeholder or broken text` | `PLACEHOLDER`, `undefined`, `[object …]` in the PDF | fix the data; placeholders never reach a sent PDF |

The checks prove the text layer; they don't see the page. Always look at the PNGs too (SKILL.md step 6).

## 6. Adding a section or a field

1. Data: add the field to `cv.ts` (a `Text` per locale; optional fields stay optional so other CVs still build).
2. Heading: a Lingui string in `CvSheet.astro`'s `sections` map (reuse the `/cv/` page's msgid when it says the same),
   `bun run i18n:extract`, translate pl + es in the `.po` files (es unreviewed).
3. Markup: an entry list goes in the `[experience, education, projects]` map (same `cs-entry` shape, free stress
   testing); a prose block uses `<section class="cs-sec">` + `h2[data-cv-heading]` + `.cs-wide`. Anything that must
   reach the text layer gets `data-cv-must`; a link that must be clickable, `data-cv-link`.
4. Sizes and gaps read `--d` (`calc(base + span * var(--d))`); colours from the tokens; no new type size without a reason.
5. Mirror it on the `/cv/` page (`CvBody.astro`) in the same order and words.
6. `bun run cv:sheet --png`, then `--stress more` (must fail cleanly) and `--stress less` (must compose: slip at the foot).

Removing a section: delete the block and its heading; nothing else depends on it. A section with no entries renders
nothing (guard it with `entries.length > 0`) rather than an empty heading.

## 7. Fonts (`bun run cv:fonts`)

Run it when a role's axes, the name (`SITE.name`), the sticker words or the charset change; commit its outputs.

- Each role is instanced from Anybody's variable font (`subset-font` `variationAxes`), renamed inside the font
  (`AnybodyCV-Regular`, `-Bold`, `-ExtraBoldCondensed`, `-ExtraBoldExpanded`, `-BlackName1/2`: parsers spot bold by the
  font name, and the variable font's default name is "Anybody-Thin"), and written as woff2 with the OFL copyright kept.
- The name: one font per word, each at the `wdth` that makes it exactly as wide as the widest word at `wdth 100`; the
  sheet sizes the h1 so the widest line fills its column (`--name-em`).
- The sticker ring + core, the running head and the page number are glyph outlines (SVG paths) from fontkit; the
  margin ones are data URIs in `@page @top-left` / `@top-right`, drawn on a 0.01 mm grid (a coarser grid looked
  jagged). The number is a fixed "2 / 2": page 1 has no margin boxes and a third page fails the print.
- Each name font is subset to its word plus a space: the sheet keeps a space at the end of the first line
  (`white-space: pre-wrap`), because Chrome builds the PDF bookmark from the laid-out text and a line break alone gave
  "MATEUSZMUSZARSKI" (a `<br>`, `aria-label`, block or inline-block lines all failed; tested 2026-10-08). Without the
  space in the subset, Chrome fell back to Times New Roman for it, which the font check caught.

## 8. Gotchas of the toolchain

- **One Astro dev and one preview server per project**, and the owner runs parallel sessions. `cv:sheet` builds into
  `.cache/cv-dist` and serves it with its own `node:http` on a random port; `--no-build` reuses that build. Never stop
  another session's server; stop yours by its port's PID.
- A running dev server may hold stale config (an old domain once): trust only the scratch build.
- `--out` resolves from `apps/web`; pass an absolute path or one relative to it.
- pdf.js v6: `getDocument({ data })` / `{ url }`, destroy with `task.destroy()`.
- Prettier puts adjacent inline children on separate lines, and Astro keeps that line break as a space: `</strong>`
  followed by a no-break space became two spaces ("Polish  native"). Where two inline pieces need exactly one space
  and no wrap, write a plain space and wrap the pair in a `nowrap` span (`.cs-lang`). Re-print and look after
  formatting the sheet.
- The PNG previews are pdf.js renders of the real PDF (not page screenshots), so they show what a recruiter's viewer
  shows, margin boxes included.
- Greyscale check: the cobalt band stays dark enough for ice text; pink markers read as mid-grey squares. Re-check after
  any colour change.
- The `pdftotext` here is xpdf 4.00, not poppler: its `-layout` mode guesses column blocks and can file a rail date
  under the wrong entry even when the baselines are identical (2026-10-08). For row pairing trust the built-in check
  or PyMuPDF (`page.get_text("text", sort=True)`); use plain `pdftotext` for the reading order.

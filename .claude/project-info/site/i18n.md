## Lingui wiring (S0 passed on the real scaffold 2026-10-05; how-to: `tech/usage/lingui.md`)

1. **Config:** `lingui.config.ts`: `sourceLocale: "en"`, `locales: ["en","pl","es"]`, fallback `en`, catalog
   `src/locales/{locale}/messages`.
   - **Extractors:** `lingui-for-astro/extractor` + babel.
   - **Scripts:** `i18n:extract` = `lingui extract --clean`. There is no compile step: `@lingui/vite-plugin` compiles `.po` on
     import, so no compiled catalog is committed (decided 2026-10-05).
   - **A missing pl/es string fails the build** (`failOnMissing: "catalog"`) and the unit test `src/locales/catalogs.test.ts`.
2. **Macros:**
   - `.astro`: `lingui-for-astro` integration + macro.
   - TSX: `@lingui/react/macro` through `unplugin-lingui-macro/vite`.
   - Plain `.ts`: `unplugin-lingui-macro`.
   - React Compiler off (it renames macro variables).
3. **Context:**
   - `src/middleware.ts` sets the request-scoped Lingui context from `params.locale` (it runs for prerendered pages).
   - React roots get **one cached `I18n` per locale** (`getI18n(locale)`) as a prop: `msg` + `i18n._()` or `t(i18n)`.
   - `<Trans>` only inside a small per-root `<I18nProvider>`.
   - Never a global `activate()` in a multi-locale build.
4. **Hydrated islands** (contact form, palette, 3D controls): receive **already-translated strings as props**, so
   no Lingui runtime or catalog ships to the browser. Prefer vanilla TS + DOM for interactions, like the
   landing (which hydrates no React at all).
5. **Long-form text is NOT Lingui:** case studies, blog posts and legal texts are per-locale content-collection
   files (`src/content/{work,blog,legal}/{en,pl,es}/…`). A test checks that each claimed locale exists and that
   headings and numbering match.
6. **Fallback if the spike fails:**
   - Lingui in React only (layouts get `title` / `description` from React-side `i18n._`), or
   - typed dictionaries like the pstrykweb.pl landing (`Dict` typing = missing key fails the build).
   - Status of `lingui-for-astro`: 0.7.1, pre-1.0, third party (SegaraRai/lingui-for); peers Astro ^5–^7, Lingui ^5–^6 [research].

## Translation workflow

- **en:** the owner's voice (`brand.md`).
- **pl:** owner-native; Claude drafts and the owner reviews high-visibility strings.
- **es:** AI translation (the owner's own `lingui-translate-ai` CLI or the `translate` skill), then a mechanical
  alignment check:
  - every msgid filled
  - placeholders and `<n>` tags identical
  - ICU plurals complete (`one/other`; pl `one/few/many/other`)
  - **es is marked unreviewed** until a native speaker reads it [user] 2026-10-05; open-questions Q19.
- Same English word with two meanings → a Lingui `context`. Interpolated values go in local variables
  (readable placeholder names).

## Formatting rules

- **Dates:** `Intl.DateTimeFormat(locale)`; timezone `Europe/Warsaw` for "local time" displays.
- **Numbers:** `Intl.NumberFormat`; pl needs `useGrouping: "always"` for 4-digit numbers [research].
- **Address forms:** pl informal "Ty" with courtesy capitals is the pstryk convention (decide in `brand.md`);
  es "tú" [assumption].
- **No raw no-break spaces or em/en dashes** in catalogs (`catalogs.test.ts`) [research].
- **Line breaks:** `typo(locale, text)` (`src/lib/typography.ts`) binds Polish/Spanish one-letter words and number + unit
  with a no-break space at render time (slice 0, 2026-10-05). Since 2026-10-08 the middleware runs the same rules over
  every rendered page (`typoHtml`: text nodes only; tags, attributes and script/style/pre/code/kbd/svg/textarea stay
  byte for byte), so titles, data files, MDX and legal text are covered too, and a `·` separator stays with the word
  before it, `§` with its number [user 2026-10-08: lonely "w" / "z" at line ends].
- **Dates in chrome follow the page:** a card's meta row (date, read time) uses the page locale even when the post is in
  another language; only the title and description carry the post's `lang` (an English post on the Spanish home showed
  "OCT 5, 2026" beside "MIN DE LECTURA", 2026-10-08).
- **Every locale is checked:** a section built or edited is checked in en, pl and es at phone, laptop and desktop
  (`bun run e2e text-fit` + side-by-side shots, `tech/usage/visual-qa.md` § Locales) [user 2026-10-08].
